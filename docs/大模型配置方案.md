# 大模型 API 可配置 · 设计方案

> 需求：模型不能写死。用户可自行配置 API 接口（Base URL / Key / 模型名），兼容国内外主流服务商与本地模型。

## 1. 为什么统一按 OpenAI 兼容协议接入

绝大多数服务商都提供 `/v1/chat/completions` 兼容端点：

| 服务商 | Base URL | 典型模型 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | deepseek-chat / deepseek-reasoner |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | qwen-plus / qwen-max |
| Kimi | `https://api.moonshot.cn/v1` | moonshot-v1-32k |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | glm-4-plus |
| 豆包（火山方舟） | `https://ark.cn-beijing.volces.com/api/v3` | doubao-pro-32k |
| OpenAI | `https://api.openai.com/v1` | gpt-4o-mini |
| Ollama / LM Studio | `http://192.168.1.x:11434/v1` | qwen2.5:7b |
| 自建网关 | 任意 | 任意 |

所以 App 只需实现 **一套 OpenAI 兼容客户端**，其余靠 Base URL + 模型名适配。对非兼容服务商（如某些国内私有协议），预留 `CustomAdapter` 接口。

## 2. 配置数据模型

```kotlin
data class LlmProfile(
    val id: String,                 // 本地唯一 ID
    val name: String,               // 显示名，如 "DeepSeek 官方"
    val baseUrl: String,
    val apiKeyRef: String,          // Key 不落普通存储，只存 Keystore 别名
    val model: String,
    val temperature: Float = 0.7f,
    val maxTokens: Int = 4096,
    val timeoutSec: Int = 60,
    val supportsJsonMode: Boolean = true,
    val extraHeaders: Map<String, String> = emptyMap(),
    val isLocal: Boolean = false
)

data class AiSettings(
    val profiles: List<LlmProfile>,
    val activeProfileId: String,
    val taskOverrides: Map<TaskType, String>,  // 每个任务可指定不同 profile
    val useCloud: Boolean = true,
    val wifiOnly: Boolean = false
)

enum class TaskType { EDIT_SCRIPT, NARRATION, TRANSLATE, SUBTITLE_FIX }
```

## 3. 密钥安全

| 项 | 做法 |
|---|---|
| 存储 | `EncryptedSharedPreferences` / Keystore AES-GCM，只存密文 |
| 显示 | 输入框 `type=password`，已保存后显示 `sk-****`，不回显明文 |
| 传输 | 仅 HTTPS（本地 `localhost`/私网 IP 允许明文，需显式开关） |
| 日志 | 统一脱敏，任何日志/崩溃上报不得包含 Key 和完整 URL 参数 |
| 导出 | 工程文件不包含 Key；迁移配置需用户重新输入 |

## 4. 请求与容错

```kotlin
interface LlmClient {
    suspend fun chat(req: ChatRequest): ChatResult
    suspend fun listModels(): List<String>
    suspend fun testConnection(): TestResult
}
```

**调用策略**

1. 超时 60 秒（可配），流式输出用于脚本页渐进展示；
2. 需要 JSON：先尝试 `response_format={"type":"json_object"}`，失败则用"纯 JSON + schema 校验"；
3. 校验失败自动重试 1 次，仍失败 → **本地规则剪法兜底**，流程不中断；
4. 429/5xx 指数退避（1s/2s/4s），不无限重试；
5. 任务级降级链：主模型 → 备用模型 → 本地规则。

## 5. 任务分工

不同任务对模型要求不同，允许各配一个：

- **剪辑脚本**：需要强逻辑与 JSON 稳定性，优先 deepseek-chat / qwen-plus；
- **解说词**：需要文风，可单独配更强模型；
- **字幕翻译**：小模型足够，省成本；
- **TTS**：走 OpenAI 兼容 `/v1/audio/speech`，也可对接国内 TTS 厂商。

## 6. API 调用示例（剪辑脚本）

```bash
curl https://api.deepseek.com/v1/chat/completions \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-chat",
    "temperature": 0.7,
    "response_format": {"type": "json_object"},
    "messages": [
      {"role": "system", "content": "你是短视频剪辑师，只输出符合 schema 的 EDL JSON。"},
      {"role": "user", "content": "<intent + clips 摘要 + 缩略图说明>"}
    ]
  }'
```

返回的 EDL 由端上 schema 校验：镜头必须引用存在的 clipId、`in < out`、总时长接近目标 ±15%，否则重试。

## 7. 配置页交互（原型第 15 屏）

1. 服务商预设一键填充 Base URL 与模型名；
2. 可改任意字段 → 自定义兼容任意网关；
3. **拉取可用模型**（GET `/v1/models`）避免手写错模型名；
4. **测试连接**：展示 200 / 延迟 / 是否支持 JSON 模式；
5. 已保存配置列表可一键切换（官方 / 本地 Ollama）；
6. 任务分工区可给不同任务指定模型；
7. 保存到本机加密存储，支持新增多套配置。
