# 智能剪辑 App —— 开源生态调研

> 调研时间：2026-10-27 ｜ 数据来源：GitHub REST API（star / 许可 / 最近推送时间均取自当日快照）
> 目标：在 Android 手机上做一个「AI 智能剪辑」App，先看清能直接复用/借鉴的开源件、它们的许可与维护状态，再定技术栈。

---

## 0. 一句话结论

**没有任何一个开源项目直接等于「手机上的智能剪辑 App」。**
能直接站在肩膀上的是三层：
1. **手动剪辑壳**（LibreCuts / open-video-editor，Kotlin + Compose/FFmpeg，MIT/GPL）——直接 fork 改造，别从零写时间线；
2. **AI 剪辑「决策层」**（auto-editor、FireRed-OpenStoryline、baocut 等，多为桌面/服务端）——**以算法或后端服务形式复用，不适合塞进 APK**；
3. **端侧能力**（Media3 Transformer、sherpa-onnx/whisper.cpp 做字幕、MediaPipe 做检测）。

推荐路线：**Kotlin + Jetpack Compose 外壳（借鉴 LibreCuts）+ Media3 Transformer 做剪辑导出 + 端侧字幕 + 云端/边缘大模型做「剪辑脚本」**，AI 只负责"决策"，渲染交给 MediaCodec/FFmpeg。

---

## 1. 第一梯队：可直接 fork 的 Android 剪辑壳

| 项目 | Star | 许可 | 语言 | 最近推送 | 结论 |
|---|---|---|---|---|---|
| [tharunbirla/LibreCuts](https://github.com/tharunbirla/LibreCuts) | 1.1k | **MIT** | Kotlin | 2026-10-26 | ★首选。功能最全的纯 Android 时间线编辑器 |
| [devhyper/open-video-editor](https://github.com/devhyper/open-video-editor) | 734 | GPL-3.0 | Kotlin | 2026-08-26 | Media3 + Compose 参考实现，商用有 GPL 传染风险 |
| [yangjie10930/EpMedia](https://github.com/yangjie10930/EpMedia) | 2.5k | MIT | C/JNI | 2021-08 | 老牌 FFmpeg 封装库，已停更，只适合抄 ffmpeg 命令拼装 |
| [SimpleMobileTools/Simple-Gallery](https://github.com/SimpleMobileTools/Simple-Gallery) | 4k | GPL-3.0 | Kotlin | 2024-08 | 相册/素材管理可参考，非剪辑 |

**LibreCuts 已实现**（可直接省掉 3~6 个月工作量）：裁剪 Trim、多段合并 Merge、文字/贴纸/图片/GIF/视频叠加、蒙版 Mask、绿幕抠像 Chroma Key、关键帧动画、`.srt` 字幕导入与拖动、图层管理、音频（BGM/配音/闪避/淡入淡出/200% 增益）、调色滤镜、变速、倒放、画布模糊背景、自由绘制、自定义字体、**工程文件保存（`.lcprj`，非破坏式）**、**MediaCodec 硬件编码导出（h264_mediacodec，失败自动回退软编）**。
⇒ 它本质是一个"手动版剪映"，**唯独没有 AI**。这正是我们的差异化空间。

**open-video-editor** 是用 Jetpack Media3（Transformer）做导出的干净范例：如果不想背 FFmpeg 的体积与 LGPL 包袱，这条路更"原生"。

## 2. 第二梯队：AI 剪辑「决策层」（不是 App，但算法直接可用）

| 项目 | Star | 许可 | 形态 | 可复用点 |
|---|---|---|---|---|
| [WyattBlue/auto-editor](https://github.com/WyattBlue/auto-editor) | 5.6k | Unlicense（最宽松） | CLI / Nim | **静音检测自动删停顿**、按音量/运动量切分；算法可照着用 Kotlin 重写 |
| [FireRedTeam/FireRed-OpenStoryline](https://github.com/FireRedTeam/FireRed-OpenStoryline) | 3.6k | Apache-2.0 | Python Agent | "把剪辑意图变成编辑动作"的 Agent 架构与 prompt 编排，最值得抄设计 |
| [JimLiu/baocut](https://github.com/JimLiu/baocut) | 1.5k | NOASSERTION⚠ | TypeScript | 可编辑时间线 + ASR 字幕 + 翻译 + 配音 + 自动切片，做 vlog 摘取的完整流程 |
| [MartinDelophy/ai-video-editor](https://github.com/MartinDelophy/ai-video-editor) | 901 | MIT | JS（本地优先） | "人和 AI 编辑同一条真实时间线"的交互与数据结构 |
| [DevonCrawford/Video-Editing-Automation](https://github.com/DevonCrawford/Video-Editing-Automation) | 1.2k | GPL-3.0 | C | 经典算法集：运动分析、镜头边界检测、自动卡点，2019 年停更但论文级实现仍在 |
| [x007xyz/flycut-caption](https://github.com/x007xyz/flycut-caption) | 1.8k | NOASSERTION⚠ | React | 字幕编辑器 UI 与 ASR 打轴交互 |

**关键判断**：这些项目的 AI 部分几乎全部依赖 PC/服务器算力（Whisper large、LLM、Nim/Python 运行时）。手机上要做同样的事，必须换成"**轻端侧 + 云决策**"：端侧只做 ASR/检测/预览，真正的"该砍哪一段、配什么 BGM、生成什么标题"交给大模型返回结构化编辑指令（EDL/JSON），再由端上渲染。

## 3. 第三梯队：底层能力件（做积木用）

| 能力 | 选型 | 说明 |
|---|---|---|
| 剪辑/导出 | **androidx/media3 Transformer**（3.1k★ Apache-2.0，活跃） | 官方推荐，硬编 h264/hevc，支持裁剪/变速/叠加/音频处理，免 NDK |
| 重滤镜/复杂合成 | **FFmpeg（LGPL 构建）+ ffmpeg-kit 替代** | ⚠ [arthenica/ffmpeg-kit](https://github.com/arthenica/ffmpeg-kit) 5.9k★ **已归档（archived）**，官方包停止维护，需自编译或换 community fork，APK 体积 +20~50MB |
| 离线字幕 | **k2-fsa/sherpa-onnx**（15.5k★ Apache-2.0，活跃）| 中文 ASR 落地最省心，ONNX 端侧运行，含 VAD/说话人分离 |
| 离线字幕（备选） | [vilassn/whisper_android](https://github.com/vilassn/whisper_android)（TFLite） / whisper.cpp | 精度好但速度慢，中低端机不友好 |
| 人脸/人物/场景检测 | MediaPipe Tasks（Apache-2.0） | 选片、自动构图、美颜、跟拍 |
| 卡点/节奏 | 自研：音频 onset + 节拍估计（aubio 思路） | auto-editor / Video-Editing-Automation 里都有现成算法 |

## 4. 竞品与商业 SDK（不开源，但要知道边界）

- **字节 CapCut/剪映**：模板 + 自动字幕 + 智能踩点，"模板生态"是护城河，个人无法复制。
- **GoPro Quik**：自动成片（Auto Highlight）体验标杆。
- **国内 SDK**：阿里云短视频 SDK、腾讯云视立方、相芯/火山 等提供美颜、特效、自动字幕的**付费闭源 SDK**——如果只想快速上线，"买能力"比"造能力"便宜，但核心 AI 剪辑逻辑仍要自研。

---

## 5. 许可风险清单（务必先看）

1. **GPL-3.0**（open-video-editor、Simple-Gallery、DevonCrawford）→ 派生必须开源，**闭源商用不可用**；
2. **FFmpeg**：LGPL 需动态链接 + 提供源码，**启用 `--enable-gpl`（x264 等）就变 GPL**；商用建议只开 LGPL 组件，或用 MediaCodec 替代编码；
3. **NOASSERTION⚠**（baocut、flycut-caption）→ 许可不明，只做**设计参考**，不要拷代码；
4. **MIT/Apache-2.0**（LibreCuts、Media3、sherpa-onnx、auto-editor）→ 商用安全，保留版权声明即可。

## 6. 差异化机会（调研后的空位）

现有开源件在手机上**都没有**：
1. **一句话成片**：给 3~10 段素材 + 一句"做个 30 秒旅行 vlog，卡点、加字幕、配轻快 BGM"，直接出片；
2. **长视频自动切片**：播客/直播录屏 → 多条竖屏短视频（baocut 有思路，但要服务端）；
3. **按说话人/剧情的智能取舍**：静音删停顿 + 口误检测 + 重复镜头剔除；
4. **模板即代码**：把"旅拍/美食/带货"的剪辑节奏做成可参数化模板（JSON 时间线），AI 只填参数——比让 AI 从零剪更稳定、更省 token；
5. **端侧优先的隐私叙事**：素材不出手机，只有文本/缩略图上行。

## 7. 建议技术栈（MVP）

```
UI        Kotlin + Jetpack Compose（参考 LibreCuts 的时间线交互）
剪辑内核   Media3 Transformer（裁剪/变速/叠加/音频/导出）
特效兜底   FFmpeg LGPL 自编（只做 Media3 做不到的：复杂滤镜、倒放、绿幕）
端侧 AI   sherpa-onnx（ASR + VAD）→ 字幕与语义段落
          MediaPipe（人脸/人物/场景）→ 选片、自动跟随
          节拍检测（自研轻量）→ 卡点
云侧 AI   LLM 生成 EDL（结构化编辑指令）+ TTS/配乐推荐
数据模型   EDL / 时间线 JSON（与 .lcprj 思路一致，可无损回编）
```

**不做的事（MVP 阶段）**：不做模板社区、不做多轨专业调色、不做云渲染、不做实时 AI 特效（耗时/发热不可控）。

| 阶段 | 周期 | 交付 |
|---|---|---|
