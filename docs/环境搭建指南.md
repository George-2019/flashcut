# FlashCut 构建环境搭建指南（手机 / ARM64 Linux）

## 更新：本机编译已经跑通 ✅

2026-10-27 已在本机成功构建出 `FlashCut-v0.1-debug.apk`（9.0MB，已签名）。
关键突破是用 **Termux 仓库的 arm64 版 aapt2** 替换 Google 官方的 x86-64 版本。

复现命令：

```bash
bash flashcut/scripts/build-apk.sh
```

产物：`app/build/outputs/apk/debug/app-debug.apk`，并自动复制为 `FlashCut-v0.1-debug.apk`。

---

## 背景：原本的两个硬门槛

| 门槛 | 实测情况 |
|---|---|
| 官方源下载速度 | Google 直连 **50–60 KB/s**，一个 SDK 包要跑一小时 |
| 国内镜像速度 | 腾讯/阿里 **9–17 MB/s**，SDK 和 Maven 依赖几分钟就够 |
| aapt2 架构 | Google 的 `build-tools` **只带 x86-64 版** `aapt2`，arm64 上无法执行 |
| 换版本也没用 | 实测 build-tools 34 / 35 的 aapt2 全是 x86-64 |
| 本地缺库 | `aapt2` 和 `libLLVM` 还需要 host 的 Zygote 依赖，本机未安装 |

所以「在手机上直接 build 出 APK」这条路成本很高，而**云端构建 + 手机安装**只要十几分钟。

---

## 方案 A：云端构建（推荐，最快）

### A1. GitHub Actions

工程已带好 `app/build.gradle.kts`，加一个 workflow 即可：

`.github/workflows/build.yml`

```yaml
name: Build FlashCut APK
on:
  push:
  workflow_dispatch:
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: '17' }
      - uses: android-actions/setup-android@v3
      - name: Build debug APK
        run: |
          gradle wrapper --gradle-version 8.13 || true
          ./gradlew :app:assembleDebug --no-daemon --stacktrace
      - uses: actions/upload-artifact@v4
        with:
          name: flashcut-debug
          path: app/build/outputs/apk/debug/*.apk
```

流程：

1. 手机上传源码包到 GitHub（可用网页版新建仓库 + 上传 zip 解压）
2. Actions 自动跑，约 **3–5 分钟**
3. 手机浏览器打开 Actions → Artifacts → 下载 `flashcut-debug.zip`
4. 解压得到 `app-debug.apk`，点击安装（需允许「安装未知应用」）

### A2. 其他云构建

- **GitHub Codespaces**：网页里直接打开 VS Code，`./gradlew assembleDebug`
- **Gitpod / 华为云 CloudIDE**：同理，浏览器里构建
- 都不需要本地装 Android Studio

## 方案 B：电脑构建（有电脑时最省事）

1. 安装 [Android Studio](https://developer.android.com/studio)（自带 JDK 17 + SDK）
2. `File → Open` 选择工程目录，等待 Gradle Sync（首次 5–10 分钟）
3. `Build → Build Bundle(s) / APK(s) → Build APK(s)`
4. 产物：`app/build/outputs/apk/debug/app-debug.apk`
5. 手机开启「USB 调试」后：

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

> 如果 `gradlew` 不存在，先执行 `gradle wrapper --gradle-version 8.13`。

### C2. 关键一步：替换成 arm64 的 aapt2（已解决）

直接从 Termux APT 仓库下载 arm64 二进制，不用编译：

```bash
BASE=https://packages.termux.dev/apt/termux-main
mkdir -p /tmp/tx && cd /tmp/tx
# 主程序
curl -LO $BASE/pool/main/a/aapt2/aapt2_16.0.0.4-4_aarch64.deb
# 依赖库
curl -L -o fmt.deb       $BASE/pool/main/f/fmt/fmt_1:12.2.0_aarch64.deb
curl -L -o libcxx.deb    $BASE/pool/main/libc/libc++/libc++_30_aarch64.deb
curl -L -o zlib.deb      $BASE/pool/main/z/zlib/zlib_1.3.2_aarch64.deb
curl -L -o libpng.deb    $BASE/pool/main/libp/libpng/libpng_1.6.59_aarch64.deb
curl -L -o expat.deb     $BASE/pool/main/libe/libexpat/libexpat_2.9.0_aarch64.deb
curl -L -o protobuf.deb  $BASE/pool/main/libp/libprotobuf/libprotobuf_2:36.2-1_aarch64.deb
curl -L -o abseil.deb    $BASE/pool/main/a/abseil-cpp/abseil-cpp_20260817.0_aarch64.deb
curl -L -o androidsup.deb $BASE/pool/main/liba/libandroid-support/libandroid-support_29-1_aarch64.deb
```

用 Python 解 deb（容器里没有 dpkg）：

```python
import glob, tarfile, io
for f in glob.glob('/tmp/tx/*.deb'):
    data = open(f,'rb').read(); off = 8
    while off + 60 <= len(data):
        hdr = data[off:off+60]; size = int(hdr[48:58].decode().strip())
        body = data[off+60:off+60+size]
        if hdr[:16].decode().startswith('data.tar'):
            tarfile.open(fileobj=io.BytesIO(body)).extractall('/tmp/tx/out')
        off += 60 + size + (size % 2)
```

安装到 SDK：

```bash
T=/tmp/tx/out/data/data/com.termux/files/usr
B=/root/android/sdk/build-tools/35.0.0
cp $T/bin/aapt2 $B/aapt2.real
cp $T/lib/*.so  $B/lib64/
# 补 .so.1 符号链接
ln -sf libz.so      $B/lib64/libz.so.1
ln -sf libexpat.so  $B/lib64/libexpat.so.1
# 包装脚本注入库路径
cat > $B/aapt2 <<'EOF'
#!/system/bin/sh
export LD_LIBRARY_PATH=/root/android/sdk/build-tools/35.0.0/lib64
exec /root/android/sdk/build-tools/35.0.0/aapt2.real "$@"
EOF
chmod +x $B/aapt2 $B/aapt2.real
```

在 `gradle.properties` 中指定：

```properties
android.aapt2FromMavenOverride=/root/android/sdk/build-tools/35.0.0/aapt2
```

### C2.1 过程中踩到的坑

| 现象 | 原因 | 解决 |
|---|---|---|
| `required file not found` | 官方 aapt2 是 x86-64 | 换 Termux arm64 版 |
| `libfmt.so not found` | Termux 二进制依赖独立库 | 从仓库补齐 libfmt/libz/libpng/libexpat/libprotobuf/abseil |
| `libz.so.1 not found` | 符号链接在 deb 里是相对链接，被复制成普通文件 | 手动 `ln -sf` 建 `.so.1` |
| `libc++ ... EM_X86_64` | build-tools 自带 x86-64 的 libc++ | 删除该文件，保留 `libc++_shared.so` |
| `License for Build-Tools 34 not accepted` | AGP 默认要 build-tools 34 | 写入 `$ANDROID_HOME/licenses/android-sdk-license`，并在 `build.gradle.kts` 里 `buildToolsVersion = "35.0.0"` |

## 常见问题

**Q：为什么 `sdkmanager --install` 很慢？**
它连的是 Google 官方清单。方案：直接用镜像下载 zip 解压到 `$ANDROID_HOME/platforms/` 等目录，绕过 sdkmanager。

**Q：`aapt2 ... cannot execute: required file not found`？**
就是架构不匹配：binfmt 找不到 `/lib64/ld-linux-x86-64.so.2`。换 arm64 版 aapt2。

**Q：构建内存不足？**
`gradle.properties` 里已经把 `-Xmx` 降到 1536m，手机 4GB 可用内存可以构建小工程；再大就上云端。

**Q：能不能直接在手机浏览器里装 APK？**
可以。GitHub Actions 产物下载后，用文件管理器点击安装，需在设置里允许该来源安装应用。
